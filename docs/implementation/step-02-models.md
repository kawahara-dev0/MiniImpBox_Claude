## 3. Implementation Notes and Assumptions

**SB-01 (Assumption): makemigrations run inside Docker container**
The Django project requires environment variables (`DJANGO_SECRET_KEY`, `POSTGRES_*`) to load `config/settings.py`. These are only available inside the running Docker container. `makemigrations` was executed via `docker compose exec app python manage.py makemigrations proposals accounts`, and migration files were copied back to the host. The generated migration files are committed verbatim.

**SB-02 (Assumption): `migrate` confirmed inside Docker container**
`python manage.py migrate` was executed inside the running container. Output shows `accounts.0001_initial... OK` and `proposals.0001_initial... OK`. Human Gate 1 verification item S2-9 requires human confirmation that the tables are visible in PostgreSQL.

**SB-03 (Assumption): `body` max_length not on model**
Per basic design Section 3.1, `body` uses `TextField` with no `max_length` at the DB level. The 2000-character limit is enforced in `ProposalForm.clean_body()` (Step 6). This is intentional per design.

**SB-04 (Assumption): `submitter_contact` is CharField not EmailField**
Per basic design Section 3.1, `submitter_contact` is a plain `CharField` to avoid incidental validation on data already in the DB. Format validation is in `ProposalForm` (Step 6). This is intentional per design.

**SB-05 (Assumption): Tests use pytest-django `@pytest.mark.django_db`**
Tests require DB access. Using `pytest.mark.django_db` per the existing `pytest.ini` / pytest-django setup from Step 1.
